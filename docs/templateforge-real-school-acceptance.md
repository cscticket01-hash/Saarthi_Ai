# TemplateForge 3 — release acceptance (not yet signed off)

**Status:** This is a test protocol, not evidence that any physical printer, school PDF, or real 1/2/5-PC cloud delivery has passed.

## Anonymized real-source corpus

Use consented school paperwork with fictitious names, financial amounts, photos, signatures, and QR destinations. Preserve the original source privately outside the repository. Record for each test: school ID alias, source SHA-256, type (receipt/reportCard/payslip), MIME/PDF page count, A4 orientation, OCR-language, print-output SHA-256, captured template version, pass/fail and the reason.

Minimum acceptance matrix (a few examples do not prove that *every* design works):

| Source | Expected evidence |
|---|---|
| Clean single-page A4 PDF with a populated receipt | Correct variable placements and arithmetic, no original student's data remains |
| Blank printed A4 JPG fee form with 12 rows | Field mapping and exact A4 print preview |
| A4 PNG marksheet, 13+ subjects | Source artwork on first page; every remaining subject printed on labelled continuation A4 pages |
| English/Hindi/Bengali/Assamese staff payslip | Correct glyphs; no fabricated salary amounts |
| Phone photo of angled white paper on dark table | Correct bounds when confidently detectable; otherwise safe rejection |
| Dim/low-contrast paper | Only verified OCR geometry accepted, never fields guessed silently |
| Mixed portrait, signature, school seal, logo, and QR placeholders | Current-person/current-school assets printed; missing or ambiguous slots reject |
| Cluttered, borderless or multi-page source | Safe rejection when there is no proven geometry |

## Physical A4 printer acceptance

1. On PR #198's **TemplateForge Windows review** successful run, open **Artifacts → templateforge-a4-print-proof**. This PDF is generated by the print acceptance test.
2. Print the proof on real A4 at **Actual Size / 100%**, with **Fit to Page disabled**. Record printer model, driver, tray setting and application print scaling.
3. Verify that both printed black lines measure **100 mm**; their starting points are **10 mm** from the top and left paper edges. Suggested engineering tolerance is **±1 mm**, not a claim of passing.
4. Print anonymized samples in each language, photo/QR combination, and continuation-page case. Measure dynamic text offset and any clipping. Require school operator approval of continuation-sheet styling.
5. Preserve actual measured results and photographs without any real student's identifiable data. A CI PASS is not the same as physical acceptance.

## Actual school-cloud / 1, 2 and 5-PC acceptance

Use a **TEST school**, no real students, and the school's own connected Drive. Each PC must use a distinct device identity and one school ID. For each fleet size (1, 2, 5):

1. **Publish:** On PC1 upload a fresh redacted A4 source. Verify the returned Drive file ID, SHA-256 readback and the manifest's sourceHash, contentHash, templateId and schoolId.
2. **Receive:** Each other PC waits for verified delta sync and reads the version. Independently download the Drive image and verify SHA-256. Record upload, ACK, and device visibility times.
3. **Select:** On PC2 choose the new version; verify PC1 through PC5 agree after sync. Print the same synthetic record. Confirm the selected version identity and PDF bytes/visible fields.
4. **Conflict:** From two offline PCs concurrently create different revisions of one document kind; reconnect. Check for lost version history, duplicated manifest records, and wrong-school exposure. Any lost update is a failure: current client-side readback checks are not full server CAS.
5. **Rollback:** Restore the previously selected version, reconnect all devices and prove that each still renders the old verified asset without deleting the newer source. Revoke access, corrupt a test asset, and disconnect a device; confirm safe failure and no active selection loss.
6. **Recovery:** Restart one PC with queued offline changes; assert no duplicate Drive upload, and no new full sync on existing devices. Check delta operation IDs, ACK evidence and school isolation.
7. **Data safety:** Verify the source never enters a second school's Drive or local cache, including identical source images across schools.

**Gate:** The PR must not be merged or made LIVE based on synthetic tests alone. Record each actual device, test date, source SHA, pass/fail, rollback evidence and operator review.

## Legal-paper and installed-printer acceptance (2026-11-01)

1. Verify a clean **US Legal 8.5 × 14 inch** school receipt in DOCX, PDF and PNG. It must stay 612 × 1008 PDF points for portrait. Verify Legal landscape is 1008 × 612 points; the source school artwork must not be stretched to A4.
2. Download the **templateforge-a4-print-proof** CI artifact containing A4 and Legal calibration PDFs. Select actual A4 or Legal paper and turn off scaling. Both 100 mm lines must measure 100 mm ±1 mm and margins must match; record printer/model/tray/driver.
3. Open the app's existing receipt print preview. Check **Add printer** opens Windows Settings > Bluetooth & devices > Printers & scanners; install a USB or TCP/IP network device using the normal signed Windows driver, return and click **Refresh printers**.
4. Confirm Windows-installed printers stay visible even if temporarily marked offline. Use **More printers / system print dialog** for Windows printer selection. Do not conclude a print succeeded merely because a job was accepted.
5. Repeat on a 1-PC, 2-PC and 5-PC TEST school using different network/USB printers where available. Compare preview page-size metadata, printed ruler measurements, original student identity and fee totals.
6. For images/QR, verify the live student's portrait and the correct school's signature/seal, with no trace of the scanned sample person's picture. Unlabelled photos and ambiguous/unbounded slots must reject rather than guess.
7. Run real Word/Excel conversions on Windows school PCs with locally installed LibreOffice/Word/Excel and inspect all printed pages for accidental extra Excel sheets or cropped Word layouts.

**Status:** No real Windows printer enumeration, physical measurement, or real 5-PC Drive rollback data has been collected here. Keep release gated until those checks are actually performed.


## Non-destructive template version retention

- Instead of deleting historical templates after three uploads, the verified school manifest retains up to 32 immutable template versions. New uploads beyond that bound are rejected until a separate reviewed archiving process exists. Old selected versions and rollback copies remain in Drive.
- The 1/2/5-device tests exercise the same manifest append helper as publication, including repeat upload and immutable-version protection. They remain synthetic: server-side atomic compare-and-swap and real concurrent online Drive publication still require live tests.
- Visual-slot recognition now requires an enclosed border on all four sides. Open ornamental rectangles are rejected rather than treated as a safe old-photo replacement target.

## On-device Windows evidence collector

For each real school PC, print the A4 or Legal calibration artifact at **Actual Size (100%)**. Measure both 100 mm lines and their top/left 10 mm margins with a ruler. Run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .github/scripts/templateforge_school_pc_acceptance.ps1 -Paper Legal -DeviceNumber 1 -PrinterName "School Printer" -CalibrationPdf ".\templateforge_legal_print_proof.pdf" -HorizontalMm 100 -VerticalMm 100 -TopMarginMm 10 -LeftMarginMm 10
```

The script reports locally installed printers, Office/LibreOffice prerequisites and operator-measured print accuracy. It never accesses student documents or Drive credentials and never claims live 5-PC sync success. Omitting measurements leaves `physicalVerified=false`. For five PCs run separately on each device; synthetic CI results cannot substitute for actual hardware.
