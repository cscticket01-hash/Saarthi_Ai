## Stage 3–4: existing engine corrections

- Calendar delete can use the existing staged records owner only with a school-bound original revision and negotiated edge capability. The final ACK requires the same operation tombstone, completed erase plan, Drive and Firebase deletion proof. Nested deletes and other deletion/cascade owners remain ordered.
- Live and staged Drive receipt polling use separate bounded readback lanes. An explicit Cloudflare status request no longer implicitly long-polls; it verifies the school/ticket and returns provider retry deadlines. No provider success is inferred from a staged ticket.
- Existing independent notice/calendar admission is extended to the Worker's attendance/expense resource policy. Unresolved person/finance/file/delete/atomic or unbound queue dependencies force those lanes to stay serial. This is source-level admission, not a measured guarantee of server concurrency.
- Troubleshoot's Run Safe Repair uses the existing sync/reconciliation owner; it does not resume pause, reset quota, or create another repair engine. Queue counts are observations, not proof of a completed repair. The graphical status includes same-school durable staged ACK timestamps separately from provider delivery.
- Android already had a delta implementation. It now requires exact advertised cached revisions and complete membership, rejects malformed/foreign-role groups, and preserves the old cache on failure. The existing Apps Script validates checkpoints before list reads and reconstructs missing scoped list baselines even when a group revision matches. Added regression source for client and Script.

Remaining code work: authenticated direct PC-to-Worker transport (current broker HMAC and online PC admission must not be exposed/bypassed), broader parent/fee/document parallel admission and all-collection canonical ACK, remaining cascade delete/recovery paths, shared repair rollout and full provider/website monitoring. Existing source changes are committed, not runtime acceptance. No new sync engine, no production deployment, no manually dispatched workflow.

## Stage 5: interrupted record handoff recovery

An explicitly authorized pending record-stage receipt now retains the exact broker-derived ticket in the existing Drive receipt journal. A later queue flush can restore the original CAS handoff after a process interruption without another mutation submission. The existing provider receipt poll can also restore that marker before accepting a final revision. Recovery is limited to the original same-school eligible pending/retry record, and rejects other operation IDs, foreign tickets, atomic/dependency-owned operations or unapproved receipts. UI diagnostic evidence checks the actual record/photo ticket digest rather than only a hash-shaped string. Canonical record completion rejects temporary live/Cloudflare revision prefixes. Added source regressions for restart recovery and wrong-ticket rejection. Historical journals without the explicit authorization marker retain their prior safe retry path; file/document and superseded-operation recovery are not covered by this change. No runtime or production verification performed in this stage.

## Stage 6: same-record staged-write ordering

For calendar/notice record writes, the existing serialized local queue now retains a known Cloudflare-owned predecessor when the user saves a newer record version, including a save arriving while the old stage response is in flight. The newer operation stays durable and is excluded from the normal send, batch, and automatic repair paths until the existing provider-receipt owner verifies the predecessor's exact ticket and canonical revision. Settlement uses the existing outbox acknowledgement transaction; it retains the newer operation, refreshes its CAS base, and invalidates stale prepared wire data. A nested deletion depending on the same predecessor retains its ordered revision. Test source covers later edits and an in-flight local save. This is not a generalized person/financial/document predecessor implementation or runtime proof. No production deployment or manually dispatched workflow.

## Stage 7: interrupted original file handoff recovery

The existing authenticated sidecar receipt journal now retains explicit authorization, the optimized file digest and (for portraits) the original raw image digest. Recovery derives the exact school/operation file ticket and restores the same original generation using the existing local CAS owner before reading or re-uploading document bytes or re-encoding an original portrait. Original document and local metadata must both match; replaced, deleted, foreign, atomic and unapproved generations are not recovered by this path. Provider-completed file replay keeps its actual verified response and leaves the receipt journal pending local CAS settlement, so a prematurely completed journal cannot strand a newly replayed file. The independent receipt poll can recover the marker before final settlement. Regression source covers interrupted photo and document settlement. Historical receipts without authorization, superseded file generations, broader parallelism, direct authenticated PC transport and runtime/production acceptance remain open. No new engine or manually dispatched workflow.

## Stage 10: recycle restore fairness and exact document handoff observation

The existing approved Recycle Bin restore owner now admits up to three evidence-ready requests per pass, rather than spending the whole window on unacknowledged original deletions. It binds each request to its same-school immutable deletion ID, collection, document ID and canonical revision; rejects a malformed retained replay rather than replacing its body; and rejects repeated inventory cursors and temporary restore revisions. Request transitions and final local settlement use the existing CAS/serialized owners with the original approved request and deletion evidence. The engine applies its existing school, quota, pause and access fences during restore dispatch. Document handoff activity now fires only after the exact local file-generation CAS committed (including restart recovery), not when a superseding save won. Added regression source for ready-restore fairness, corrupted replay and temporary ACK refusal. No runtime tests or production deployment were performed. Direct authenticated Worker transport, generalized person/financial/document concurrency, all-collection canonical delete completion, wider automatic/shared repair rollout and provider/device verification remain open; these are not implied complete by commit count.
