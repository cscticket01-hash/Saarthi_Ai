# Document conflict and readable student Sheet recovery

Continues published main `16b9b6e8afe586aee9e9e702402dd523808114f5`. No existing catalog IDs or repair actions are replaced.

## Confirmed source issues and resulting behavior

- Managed Sync calls ID generation before its cloud pull. A missing local generation can create another PDF for the same owner without knowing an existing cloud generation. Initial publication now reads authenticated published-document metadata before committing a new generation, outside the local file writer. Matching input fingerprints restore cloud metadata and suppress another upload; different inputs retain a conflict for explicit review. Timeout/offline reads never grant a replacement baseline. A batch shares one inventory request. Same-input cached cloud metadata avoids repeated rendering. This source path is demonstrated by a fixture; the exact cause of the user's historical PDF difference remains unconfirmed.
- The differing-document review UI previously had no resolution controls. It now previews both PDFs and offers explicit local/cloud selection with confirmation and a reason. Local selection produces a new immutable operation with both document and record CAS baselines. Upload and cloud ACK still belong exclusively to Smart Sync. Cloud selection hashes authenticated downloaded bytes, repeats cloud revision readback, independently hashes the flushed disk copy, and retains a separate local copy with its usable file extension; it is never an ACK of the rejected local operation. A cloud choice is not immediately undone by unchanged local ID inputs.
- Ordinary document queue writes deliberately preserve conflicts. A dedicated owner review transition rechecks the exact queue and local generation inside the serialized durable write; SQLite loads only the four affected collections and exact record IDs. It archives the original decision and writes the selected generation atomically. Ordinary writes retain the existing guard. Local bytes are checked against the hash displayed during review; changed bytes, changed cloud/owner/school, deletion and duplicate review are rejected.
- Managed student rows previously exposed only generic JSON chunks. Fourteen readable student columns, including readable wire timestamps, now derive from the same canonical row; canonical columns are hidden for display, retained for Sync. Existing records backfill in batches of at most 100 per authenticated read, without revision changes or another store. Projection errors preserve canonical ACKs and owner cells and appear in signed health status. Headers belonging to someone else block projection. Formula-like strings remain inert. Organized partitions use the same implementation.
- `Verify student cloud records` performs a full authenticated own-school metadata snapshot comparison, bounded to 10,000 records per side. It reports matching, missing-cloud, different, cloud-only and pending IDs. It rejects school switching, unbound/foreign data and local edits during verification. It never writes records or clears queues. Differences can include locally retained media fields; this is not byte verification or a full end-to-end certification.
- Self-Healing conflict guidance names the owner source files and the exact review steps. The 1,000 diagnostic IDs and eight registered executable actions remain. No new automatic conflict-winner permission is granted.

## Validation and publication boundary

Dedicated tests cover owner decisions, retained bytes, restart, duplicate recovery, changing local/cloud versions, school switching, corrupt download, timeout after possible commit and same-input restored ID suppression. Existing queue, UI, receipt, revision and monitor regressions are included in a Windows/Linux review workflow; the existing platform workflow checks Windows, Android, Web, backend and school security on the Draft PR.

This change does not deploy, release, run school setup, bind a new school or operate on real school records. The Apps Script source bundle is generated from its reviewed sources. An existing-school upgrade must preserve Script Properties, deployment identity, school/root/secret and `/exec` URL. Do not rerun setup. New binaries and an existing-school Script upgrade are required after review approval. Original-school cloud readback, physical Windows/Android and printer acceptance are not certified by synthetic tests.
