# Global ID Card Library — phase 1

Developer-approved scope: website Global Features, Firebase Storage and Firestore, existing Render school broker, no Cloudflare changes. All current designs free; no payment processing or gateway credentials. Signature, PIN, address geometry and PR #438 are explicitly out of scope.

Implemented: private original PDF upload (8 MiB first-stage limit, fictional sample and artwork rights confirmation), checksum readback, category list, draft/archive/restore, server-only metadata, authenticated managed school catalog projection and version-scoped manual grant foundation. No direct client writes to global library, entitlement or purchase collections. Existing developer and school membership/licence guards reused. No download URLs or original source exposed to schools. Header/footer validation is only input screening; no parsing, extraction or automatic approval claimed.

Deployment prerequisite: verify exact existing Firebase bucket, private object IAM and no public bucket access or download tokens; set SAARTHI_GLOBAL_ID_CARD_BUCKET on the existing Render service only after authorized staging verification. No bucket or environment change in this PR. The bucket remains disabled by default. Isolated TEST broker has no global production bucket.

Remaining phases: safe central PDF parsing/rendering, OCR and semantic field detection, exact font and physical geometry detection, removal of sample text/photo/logo/signature/seal/QR, source-to-clean-artwork verification, human review when uncertain, immutable sanitized package and version publication/rollback. Then Windows registry refresh, verified school-scoped offline cache and preview/print/download/bulk integration, premium catalog previews and entitlement enforcement. Payment provider and checkout remain disabled; future verified provider receipts must be server-created, idempotent and school/version-bound. No school can use a draft. No publication route intentionally exists yet. A true permanent deletion/retention policy and failed-upload orphan reconciliation require review before activation.

Tests added to existing Node test suite, not manually run. No new workflow or deployment.

## Phase 2 — bounded candidate analysis and reviewed publication

Added an optional central Poppler pdftotext runtime (SAARTHI_GLOBAL_ID_PDFTOTEXT, explicit executable configuration and external process sandbox required). Analysis extracts labeled vector-text geometry candidates only. It does NOT prove image/QR removal, font preservation or complete mapping. Operator reviews a separately prepared clean PNG+manifest JSON package, confirms sample removal, and publishes immutable hash-verified bytes to Firebase Storage. Server validates bounded physical geometry, known fields/labels, QR size, collisions and PNG container/dimensions. It cannot prove pixel-level sample removal or font equivalence. Original sources are never distributed. Package retrieval is authenticated by existing school membership, active licence and version entitlement. All new templates remain free; no payment collection. New revisions presently require new template IDs; a version/rollback UI remains pending. This is a reviewed manual fallback, NOT the final upload-only automation.

## Phase 3 — Windows global registry integration

Added Windows managed-school remote catalog, one-minute metadata refresh while Document Templates is open, immutable SHA-256 checked package retrieval and in-memory cache, verified school/profile scope, native gallery preview and explicit selection of remote manifest, HD single and bulk export support, and server access check before export. Built-in catalog and existing selections are retained; remote template failure does not replace an existing selection. Remote geometry cannot be edited through bundled-template designer. Current free templates only are exposed; no offline lease, paid unlock UI, persistent disk cache or production activation yet. Full offline access, remote template thumbnails, robust per-version update/rollback and automatic image/text cleanup still require implementation and acceptance. Existing school identity/UID and sync paths unchanged; no geometry edits to existing card assets. No manual CI run.

## Phase 4 — automatic candidate analysis and disk reuse

Upload attempts text and optional embedded-image geometry analysis after durable source registration, with private review-required status or retryable draft on failure. Optional SAARTHI_GLOBAL_ID_PDFTOHTML runtime extracts bounded unclassified image rectangles; it does not classify images or remove sample pixels. The central Poppler tools must run with externally enforced isolation and resource limits before activation. Added school/profile-scoped disk cache of validated clean packages keyed by template/version/hash; cache hits still require live server authorization. It is not an offline entitlement, and no premium offline key or payment collection is introduced. No existing template geometry, Sync Engine or CI workflow changed.

## Versioned library

A new revision has a unique immutable catalog ID and a shared family ID. A transaction assigns monotonic version numbers; published existing revisions remain selectable and school selections stay pinned. Developer can promote or restore a verified previous revision after storage checksum readback. Archive removes that revision from the active catalog without deleting source/package bytes. Current marker is metadata only; Windows accepts v1+ and preserves existing selection IDs. Older unverified drafts cannot be promoted. Existing free policy stays unchanged. History is bounded by the current 200-row library query; pagination and retention policy are separate scalability work.

## Free-only offline catalogue lease

The authenticated managed school list returns account UID, server time and an expiry bounded by the school licence and 24 hours. Windows uses the existing WindowsSecureStorage wrapper to retain only authorized FREE metadata; cache scope binds local profile, school, account and endpoint. Temporary network failures may use the exact unexpired free package already downloaded and hash-verified. Authoritative denials invalidate cached metadata. No premium offline access, payment activation, or licence extension. New downloads still need connectivity. Built-in lookups do not contact the global registry. The local free lease is not cryptographically signed DRM; physical Windows testing, clock/expiry and revoke acceptance remain required.

## Assisted visual PDF review

Added optional isolated SAARTHI_GLOBAL_ID_PDFTOPPM runtime for developer-only 600 DPI source rasters. The website mapping editor initializes text/image rectangle candidates, allows role, coordinates, font size, text color, wrap and shape review and missing field slots. For flat backgrounds, bounded raster cleanup replaces sample-region pixels using a uniform exterior color while keeping original bytes and other pixels untouched. Nonuniform background or edge contact rejects automatic cleanup, rather than inventing a background. A reviewed clean artwork package remains the fallback. Final human verification of all sample elements is required. Automatic semantic image roles, arbitrary gradient/pattern reconstruction, exact font-family reproduction and configuration/physical tests are still not complete. Only the reviewed sanitized package can be distributed.

Text candidate extraction now groups separately positioned Canva text blocks by vertical geometry and recognizes multiple labeled fields on a line. Visual review suggests a QR role only when exactly one embedded-image candidate actually decodes using the existing ZXing dependency, without retaining the sample payload. Other image roles remain review-required; vector-only QR and unlabeled elements may need manual mapping. Regression fixtures use fictional sample values only.
